## 貳、 物聯網與系統觸發技術 (IoT & System Triggers)

此部分將高達百種的觸發與通訊技術分為五大核心領域，並補充其延遲特性與技術細節。

### 1. 應用層、訊息傳遞與 API (Application Layer & Messaging)

用於系統間對接、雲端與邊緣運算的資料交換。

|**技術 / 協定**|**網路媒介**|**典型延遲**|**複雜度**|**技術細節與應用場景**|
|---|---|---|---|---|
|**REST API / Webhook**|乙太網路 (IP)|<50ms (LAN)|低至中|現代 Web 服務的基礎，Webhook 用於被動接收事件觸發（如付款成功通知）。|
|**MQTT / MQTT-SN**|乙太網路 (IP)|<50ms (LAN)|低|輕量級發布/訂閱 (Pub/Sub) 協定，物聯網資料傳輸的業界標準。|
|**AMQP / RabbitMQ**|乙太網路 (IP)|<10ms (LAN)|中|企業級訊息佇列協定，確保訊息可靠傳遞，適合金融或高穩定度需求的後台處理。|
|**Apache Kafka**|乙太網路 (IP)|<50ms (LAN)|中|高吞吐量的分散式串流處理平台，用於即時大數據分析與日誌聚合。|
|**CoAP**|乙太網路 (IP)|<10ms (LAN)|中低|專為受限設備 (微控制器) 設計的類 HTTP 協定，基於 UDP，適合低功耗感測器。|
|**gRPC (HTTP/2)**|乙太網路 (IP)|<5ms (LAN)|中高|Google 開發的高效能 RPC 框架，使用 Protobuf，非常適合微服務之間的低延遲通訊。|
|**GraphQL API**|乙太網路 (IP)|<50ms (LAN)|中高|允許客戶端精確定義所需資料結構的 API 查詢語言，減少資料過度獲取。|

### 2. 無線通訊與低功耗廣域網 (Wireless & LPWAN)

適合廣闊場域、移動設備或無法拉線的環境。

|**技術 / 協定**|**網路媒介**|**典型延遲**|**複雜度**|**技術細節與應用場景**|
|---|---|---|---|---|
|**LoRaWAN**|RF ISM (無線電)|1-10 秒|中|長距離、低功耗，適合智慧農業、環境監測，資料傳輸量小但覆蓋範圍極廣。|
|**NB-IoT / LTE-M**|蜂巢 LPWAN|100ms - 數秒|中|基於電信商基站的低功耗物聯網技術，適合智慧水表/電表、地下室設備監測。|
|**Bluetooth LE / BLE Mesh**|RF 2.4GHz|10-200ms|中|藍牙低功耗與網狀網路，常用於室內定位、智慧照明與消費性穿戴裝置。|
|**Z-Wave / Zigbee**|RF Sub-GHz / 2.4GHz|<100ms|中低|智慧家庭的主流標準，具備網狀網路特性，適合家庭自動化與門窗感測。|
|**Private 5G / LTE**|私有蜂巢網路|5-30ms|極高|企業專網，提供極低延遲與高頻寬，專供智慧工廠 (AMR/AGV) 或高機密場域使用。|
|**Satellite IoT**|衛星 (無線)|10s - 60s|中高|如 Iridium、Starlink D2C，用於海上、沙漠等無基地台覆蓋的極端偏遠地區。|

### 3. 工業控制與自動化匯流排 (Industrial & Control Buses)

用於工廠自動化 (OT)、建築管理與車載系統。

|**技術 / 協定**|**網路媒介**|**典型延遲**|**複雜度**|**技術細節與應用場景**|
|---|---|---|---|---|
|**Modbus TCP / RTU**|乙太網路 / RS-485|<10ms / <20ms|低|工業界最古老也最普及的協定，採用主從架構，用於 PLC 與感測器通訊。|
|**BACnet/IP**|乙太網路 (IP)|<50ms (LAN)|中|建築自動化標準，用於控制 HVAC (空調)、照明、門禁與電梯系統。|
|**OPC UA**|乙太網路 (IP)|10-100ms|高|工業 4.0 的核心通訊標準，具備跨平台能力與強大的安全及資料建模機制。|
|**CAN bus / J1939**|工業現場匯流排|毫秒級|中|車輛與重型機械的內部神經系統，抗干擾能力極強，用於引擎與煞車控制。|
|**EtherCAT / PROFINET**|乙太網路線路|<50ms (LAN)|中|工業乙太網路標準，提供極高的實時性，用於高精度的馬達控制與機器人技術。|

### 4. 硬體接點與實體層觸發 (Hardware & Physical Triggers)

最基礎且直接的電氣觸發方式。

|**技術 / 協定**|**網路媒介**|**典型延遲**|**複雜度**|**技術細節與應用場景**|
|---|---|---|---|---|
|**Dry Contact (乾接點)**|實體有線 (繼電器)|<5ms|極低|無電壓的物理開關接點，廣泛用於火警警報、緊急停止按鈕 (E-stop) 或門磁感測。|
|**GPIO / I/O Module**|實體有線 / IP 模組|毫秒級|中|通用型輸入輸出，可直接控制 LED、繼電器或讀取微動開關狀態。|
|**Current-loop 4-20mA**|工業感測器匯流排|毫秒級|中|工業標準類比訊號，抗雜訊能力強，常用於長距離傳輸溫度、壓力或液位數據。|
|**I2C / SPI**|板級匯流排|毫秒級|中|印刷電路板 (PCB) 上的短距離通訊，用於微控制器 (MCU) 與感測器 IC 之間的連接。|

### 5. 語音、電信與多媒體信令 (Voice, Telecom & Multimedia)

用於通訊系統內的狀態控制與事件觸發。

|**技術 / 協定**|**網路媒介**|**典型延遲**|**複雜度**|**技術細節與應用場景**|
|---|---|---|---|---|
|**SIP (NOTIFY/MESSAGE)**|乙太網路 (IP)|<50ms|中|會話發起協定，除了語音通話外，也可用於設備狀態訂閱與即時文字指令傳送。|
|**DTMF over VoIP**|乙太網路 (IP)|<50ms|中|雙音多頻 (按鍵音)，常在語音通話中用於觸發 IVR 菜單或開門指令 (RFC 4733)。|
|**WebRTC Data Channel**|乙太網路 (IP)|<10ms (LAN)|高|支援瀏覽器間點對點的即時語音/視訊與任意數據傳輸，極低延遲，適合遠端遙控。|
|**SMS / GSM AT Cmd**|蜂巢網路|1-30 秒|低|傳統簡訊觸發與數據機控制指令，用於喚醒遠端設備或發送低頻率警報。|

**💡 架構設計建議 (Design Tips)：**

- **選擇考量：** 在進行系統整合時，若追求**低延遲與高穩定**（如工廠產線），應優先採用 **Dry Contact、EtherCAT 或 Modbus TCP**；若考量**廣域部署與低功耗**，則 **LoRaWAN 或 NB-IoT** 是最佳選擇。
    
- **雲端整合：** 現代物聯網架構強烈建議將邊緣設備的異質協定（如 Modbus、CAN、BLE）透過物聯網閘道器（IoT Gateway）統一轉換為 **MQTT 或 REST API**，以利與 AWS、GCP 或企業自建的系統介接。
