Redis 詳細技術解說

Redis 是一個以**極速**著稱的資料庫系統，其核心設計是基於**鍵值對（Key-Value pairs）**的對應關係。在 Redis 中，**鍵（Key）**是用於存取資料的標籤，而**值（Value）**則是實際存儲的內容。

一、 Redis 的三種部署方案

Redis 提供三種不同的版本以滿足各種需求：

- **Redis Community Edition（社群版）**：可安裝於本地機器，支援透過原始碼編譯或 Docker 容器執行，適合開發與測試。
- **Redis Cloud**：全託管的雲端資料庫服務（DBaaS），提供免費版（Free）、基礎版（Essentials）與專業版（Pro），支援自動故障轉移（Auto failover）與多區域部署。
- **Redis Software**：企業級自管解決方案，可部署於地端環境或私有雲。

二、 核心數據結構（Data Structures）

Redis 不僅能存儲簡單的字串，還支援多種複雜的數據結構：

1. 字串 (Strings)

- **特性**：最基礎的數據結構，是**二進位安全（Binary safe）**的位元組序列。
- **用途**：除了純文字與數字（可進行增減運算），還能存取序列化的 JSON、影像、影片或音訊檔。
- **指令**：使用 `SET` 存入值，`GET` 讀取值。

2. 列表 (Lists)

- **特性**：**有序**的字串集合，允許重複元素。
- **操作**：支援從左側（Head）或右側（Tail）進行 `PUSH`（新增）與 `POP`（移除並回傳）。
- **用途**：非常適合實作**隊列（Queue）**、**堆疊（Stack）**或記錄最近瀏覽物品。

3. 集合 (Sets)

- **特性**：**無序**且**唯一**的字串集合，會自動去重。
- **功能**：支援數學上的集合運算，如**聯集（Union）**、**交集（Intersection）****差集（Difference）**。
- **用途**：追蹤不重複的造訪者、數據去重。

4. 雜湊 (Hashes)

- **特性**：欄位（Field）與值（Value）的對應集合，其內部結構就像是資料庫中的一筆記錄。
- **用途**：存儲**使用者工作階段（Session data）**或對象記錄（如產品資訊）。

5. 有序集合 (Sorted Sets)

- **特性**：類似集合，但每個成員都關聯一個**分數（Score）**，Redis 會根據分數進行排序。
- **用途**：製作**排行榜（Leaderboards）**或推薦引擎。

6. JSON

- **特性**：支援存儲嵌套的 JSON 文件，並能透過 **JSON Path** 查詢或修改特定欄位，而無需反序列化整個字串。
- **優勢**：支援強型別資料（如 Boolean、Numbers）。

三、 進階與特殊數據結構

1. 機率性數據結構 (Probabilistic Data Structures)

這類結構犧牲了一定的準確性來換取**極小的記憶體佔用**與**極快的執行速度**：

- **HyperLogLog**：用於計算**基數（Cardinality）**，即不重複項目的數量，誤差率僅約 0.81%。
- **Bloom Filter（布隆過濾器）**：測試成員是否存在。回傳「否」代表絕對不存在，回傳「是」代表可能存在（有誤報可能）。

2. 串流 (Streams)

- **特性**：按時間順序記錄事件歷史，每個事件都有唯一 ID。
- **用途**：作為服務間通訊的**事件匯流排（Event Bus）**或記錄使用者點擊流。

3. 地理空間索引 (Geospatial Indices)

- 存儲成員的**經緯度**，支援半徑搜尋、計算距離或查詢座標。

4. 向量資料庫 (Vector Database)

- 將資料（如圖片、PDF）轉化為**向量（Vectors/Embeddings）****語義搜尋（Semantic search）**、生成式 AI 應用與推薦系統。

--------------------------------------------------------------------------------

四、 關鍵功能管理

1. 鍵值過期機制 (Key Expiration)

- **持久鍵（Persistent Keys）**：除非手動刪除，否則永久存在。
- **揮發鍵（Volatile Keys）**：設定有**存活時間（TTL）**，到期後會自動刪除。這是實現**快取（Caching）**的核心功能。

2. 鍵名規範與命名空間 (Key Spaces)

- 建議使用一致的命名約定，例如使用冒號（`:`）分隔不同層級的字首（Prefix），如 `app:config:service`。

3. 管理工具：Redis Insight

- 這是一個強大的**圖形化界面（GUI）**工具，可用於視覺化數據、執行指令、分析性能瓶頸以及管理數據結構。

--------------------------------------------------------------------------------

五、 主要應用場景 (Use Cases)

- **企業級快取（Caching）**：利用 Redis 的速度（通常回應低於 1 毫秒）來減輕後端資料庫負擔，加速網頁載入。
- **搜尋與查詢（Search & Query）**：對 Hash 與 JSON 進行複雜的多維度查詢。
- **工作階段管理（Session Management）**：提供低延遲的分布式 Session 存取，確保使用者在不同伺服器間切換時購物車資訊不會遺失。
- **AI 與向量搜尋**：儲存非結構化資料，支援聊天機器人與推薦引擎。
