# 1. Redundant / Resilient Architecture vs Egress Monitoring

題庫暗示 redundancy / resilience 本身不構成 egress monitoring 障礙，這太絕對。

## 正確模型

如果只是單純 HA：

```text
Application
    ↓
One logical egress point
    ↓
HA firewall pair
    ↓
Internet
```

底層 redundancy 對監控複雜度可能很小。

但若 resilience 代表：

```text
Region A → Egress A
Region B → Egress B
Region C → Egress C
```

再加上 multi-account、multi-VPC/VNet、autoscaling、ephemeral instances、multiple NAT gateways、multiple proxies、failover paths，就會增加：

- sensor / agent deployment
- policy synchronization
- baseline consistency
- log normalization
- configuration drift
- visibility gaps
- failover-path coverage
- privilege / access requirements

## 最短模型

```text
Egress monitoring difficulty
≈
Number of egress paths
× Visibility gaps
× Policy/config copies
× Privilege limitations
```

**Rule：** Redundancy 本身不一定造成監控困難；分散式、多路徑 resilience architecture 很可能會。

**分類：** `[Q]`  
**降權：** 高

# 2. Maintenance Mode

## 核心

Maintenance mode 的目的不是把管理員鎖掉，而是：

```text
Stop / evacuate normal production workloads
→ Prevent normal new workload placement
→ KEEP administrative access
→ KEEP logging
→ Perform maintenance
```

管理員可能需要 patch、upgrade、diagnostics、hardware/hypervisor maintenance、service restart。

所以：

> **Admin access is prevented**

明顯不合理。

## 題庫 wording 問題

> Generation of new instances is prevented.

太絕對。

比較精確應是：

> **Normal production workload placement onto the node is prevented / avoided.**

因為 maintenance/system/admin workload、service restart、agent、DaemonSet-like workload 等仍可能產生。

## 最短模型

> **停業務，不停管理。**

**分類：** `[Q]`  
**降權：** 中

# 3. BC/DR：Returning to Normal Operations Too Late

題庫把：

> Returning to normal operations too late

視為「most significant organizational risk」，但沒有給 business context，這個比較不乾淨。

## Cause / Event / Consequence

```text
Recovery capability failure
        ↓
Cannot restore required service
        ↓
RTO exceeded
        ↓
MTD / MAD exceeded
        ↓
Unacceptable business impact
```

因此 `returning too late` 更像 **recovery failure 的 outcome / consequence**。

## Confidentiality 不會因 DR 自動失去重要性

BC/DR 強調 availability，但不代表：

```text
Availability > Confidentiality
```

永遠成立。

Hospital、payment processor、HSM/key custodian、regulated financial institution 等，在 contingency 中若發生 confidentiality breach，也可能造成不可逆的法律、財務與安全影響。

## 正確 timeline

```text
Disaster
   ↓
RTO
   ↓
WRT
   ↓
Normal business operation
```

關係：

```text
RTO + WRT ≤ MTD / MAD
```

- **RTO**：IT/service 恢復時間
- **WRT**：系統恢復後讓業務回到正常所需時間
- **MTD/MAD**：最大可容忍中斷時間

## Judgment Rule

題目若問「如何避免超過最大停機時間」：
→ 優先想 `RTO / WRT / MTD`

題目若問「greatest organizational risk」：
→ 先找產業、資料敏感度、法規、安全影響、business criticality。

沒有 context 的絕對排名應提高警覺。

**分類：** `[Q]`  
**降權：** 高

# 4. BC/DR 弱點分級更新

你目前已能穩定畫出：

```text
Disaster
→ RTO
→ WRT
→ Back to normal
```

且知道：

```text
RTO + WRT ≤ MTD/MAD
```

所以：

> **BC/DR timeline：P0 → P1 / Maintenance**

這輪的錯誤不再視為 timeline 知識缺口，而是題庫 judgment / wording 問題。

---

# 5. 今天要背的 5 條 Rule

1. **分散式 redundancy 可能增加 monitoring complexity。**
2. **Maintenance mode：停正常 workload，不停 admin access。**
3. **Prevent normal production placement ≠ prohibit every possible new instance。**
4. **RTO + WRT ≤ MTD/MAD。**
5. **Greatest-risk 題若沒有 business context，不要把 availability 當絕對第一。**

# 6. 閃卡

## Card 1
**Q：Redundant / resilient architecture 一定不影響 egress monitoring 嗎？**  
A：不一定。若形成 multi-region、multi-egress、multi-account 或 failover paths，會增加 sensor deployment、policy sync、baseline consistency、log normalization 與 visibility gap。

## Card 2
**Q：Egress monitoring complexity 最短模型？**  
A：`Egress paths × Visibility gaps × Policy/config copies × Privilege limitations`

## Card 3
**Q：Maintenance mode 最短定義？**  
A：停止或移出正常 production workload，保留管理能力進行維護。

## Card 4
**Q：Maintenance mode 會阻止 admin access 嗎？**  
A：不會。管理員必須保留 access 才能 patch、upgrade、diagnose、repair。

## Card 5
**Q：`Generation of new instances is prevented` 為何太絕對？**  
A：真正意義是避免正常 production workload placement；maintenance/system/admin workload 仍可能產生。

## Card 6
**Q：Maintenance mode 口訣？**  
A：**停業務，不停管理。**

## Card 7
**Q：RTO、WRT、MTD/MAD 的核心關係？**  
A：`RTO + WRT ≤ MTD/MAD`

## Card 8
**Q：RTO 是什麼？**  
A：IT/service 從中斷到恢復可用的目標時間。

## Card 9
**Q：WRT 是什麼？**  
A：系統恢復後，讓業務流程與營運回到正常狀態所需時間。

## Card 10
**Q：Returning to normal operations too late 是 root risk 還是 outcome？**  
A：通常更接近 recovery failure 的 outcome / consequence。

## Card 11
**Q：BC/DR 情境下 Availability 一定比 Confidentiality 重要嗎？**  
A：不一定。要看業務、法規、資料敏感度與安全影響。

## Card 12
**Q：題目問 greatest organizational risk 時，第一個要找什麼？**  
A：Business context：產業、資料敏感度、法規、安全影響、RTO/MTD criticality。

## Card 13
**Q：今天三題的降權？**  
A：
- Redundant architecture vs monitoring → `[Q]` 高
- Maintenance `new instances prevented` → `[Q]` 中
- Returning too late = greatest risk → `[Q]` 高
