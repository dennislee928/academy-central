# 1. Process Isolation（程序隔離）

## 1.1 一句話定義

> **Process isolation = 每個執行中的程序（process）維持獨立執行域（execution domain），避免一個程序任意讀寫、修改或影響另一個程序。**

NIST SC-39 的核心就是：不同 process 有分離的 address space／execution domain，process 之間的互動要經過受控機制。

### 最短模型

```text
Process isolation
= separate execution domain
= process A 不能任意碰 process B 的 memory/code/state
```

---

## 1.2 它「不是」什麼

### 不是 Network Isolation

```text
Process isolation  → 隔離執行域 / memory / process state
Network isolation  → 隔離 network path / zone / segment / traffic
```

所以：

> **Process isolation 完全可以存在於一台可直接連 Internet 的主機內。**

有 TLS、DNSSEC、VPN 不代表 process isolation；那是通訊／網路安全控制。

### 不是「完全沒有 side channel」

Process isolation 可以防：

- 直接 memory access
- 直接 code modification
- 部分 IPC 越權
- 某些 process escape 路徑

但不能直接保證消除：

- CPU cache timing
- speculative execution side channel
- shared hardware contention
- hypervisor / container escape

所以：

```text
Process isolation
≠ complete hardware isolation
≠ proof against every side channel
```

---

## 1.3 常見實作層次

| 層次 | 例子 | 隔離重點 |
|---|---|---|
| OS Process | virtual address space、privilege boundary | process ↔ process |
| Sandbox | restricted process / capability | untrusted code ↔ host resources |
| Container | namespace + capability + cgroup 等 | workload ↔ workload / host |
| VM | hypervisor mediated isolation | guest ↔ guest |
| Hardware-assisted | MMU/IOMMU、hardware separation | 更強的 memory/device boundary |

> 注意：Container 是一種 process isolation 技術，但「container = 完整 security boundary」不能無條件成立。

---

## 1.4 為什麼 LearnZapp 在 Secure Software Development 題選 Process Isolation？

題目雖然寫：

> secure software development for the cloud

但它想測的是：

> **在設計／開發 cloud software 時，必須考慮 shared-resource runtime isolation。**

你之前卡住的點合理：`process isolation` 聽起來很 runtime。

正確修正不是改成「上位詞永遠優先」，而是：

### 題型判斷規則

1. 先看選項是否是**正式、可驗證的安全概念**。
2. 再看是否直接回答題幹的 security property。
3. 泛稱若沒有明確定義，不因為「比較上位」就勝出。

所以：

```text
Enhancement mechanisms
= 太泛、沒有足夠分類能力

Process isolation
= 明確 security mechanism
= 直接對 shared-resource / side-channel / workload separation
```

### 最短口訣

> **上位詞不是自動優先；「可驗證、可映射題幹」才優先。**

# 2. ISO/IEC 27018

## 2.1 2026 應該背哪個版本？

目前應以：

> **ISO/IEC 27018:2025**

為現行版本；2019 版已被取代。

---

## 2.2 一句話定位

> **ISO/IEC 27018 = 公有雲（public cloud）中，當 CSP 以 PII processor 身分處理個資時的隱私保護指南。**

最短 trigger：

```text
Public cloud
+ PII
+ cloud provider acting as processor
→ ISO 27018
```

---

## 2.3 它和其他 ISO 的關係

| Standard | 最短定位 |
|---|---|
| ISO/IEC 27001 | ISMS requirements，可做認證主體 |
| ISO/IEC 27002 | Security controls guidance |
| ISO/IEC 27017 | Cloud security controls guidance |
| **ISO/IEC 27018** | **PII in public cloud when CSP is processor** |
| ISO/IEC 27701 | Privacy Information Management System（PIMS）擴充 |

### 記憶法

```text
27001 = 管理系統要求
27002 = 一般 controls
27017 = Cloud
27018 = Cloud PII
27701 = Privacy management
```

口訣：

> **17 雲安全，18 雲隱私。**

---

## 2.4 它「不是」什麼

- 不是 privacy law
- 不是只適用 controller
- 不是所有雲都自動適用
- 不是 PCI DSS
- 不是 NIST RMF
- 不要背成「ISO 27018 = 每年 audit」

題目若問：

> first international privacy standard specifically for cloud providers

LearnZapp 想對應 ISO 27018；考場層級只要能辨識即可，**不用背歷史首發年份或版本 trivia**。

# 3. Secure KVM

## 3.1 KVM 是什麼？

```text
K = Keyboard
V = Video
M = Mouse
```

KVM switch 讓一套 keyboard / display / mouse 在多台電腦間切換。

**Secure KVM** 的安全問題不是「能不能切換」，而是：

> **切換時不能讓 Computer A 與 Computer B 透過共享周邊形成跨域資料通道。**

---

## 3.2 Secure KVM 最重要的 security properties

### 最短模型

```text
One peripheral set
→ one selected computer at a time
→ no cross-computer data leakage
```

常見能力：

- dedicated / separated data paths
- selected-channel indication
- explicit switching（常見為實體按鈕）
- filtering / emulation of keyboard and mouse
- peripheral device filtering
- buffer clearing
- restricted data flow
- tamper resistance / protected enclosure
- audio/video data-flow control

官方 Secure KVM / Peripheral Sharing Device 評估資料的重點是：**data isolation / user data protection / prevention of unintended cross-domain flow**。

---

## 3.3 為什麼 TPM 不是 Secure KVM 的必要特徵？

TPM（Trusted Platform Module）的核心用途：

- device/platform trust
- secure key storage
- measured/verified boot support
- attestation 等

它是：

> **endpoint/platform security primitive**

不是：

> **peripheral-sharing isolation primitive**

你之前舉 Windows Hello / Touch ID 的例子沒有錯，但那代表：

```text
connected endpoint may use TPM / Secure Enclave
```

不是：

```text
Secure KVM itself must contain TPM
```

### 最短口訣

> **TPM 保主機；Secure KVM 保跨主機周邊路徑。**

---

## 3.4 這題值得背多深？

低到中優先。

要會：

- Secure KVM = cross-domain peripheral isolation
- push-button / explicit selector 合理
- buffer/data-path isolation 合理
- TPM 不是典型必備功能

不用背：

- 特定廠牌 PCB layout
- 每一版 Protection Profile 細項

# 4. TPI（Two-Person Integrity，雙人完整性／雙人共同控制）

## 4.1 一句話

> **敏感資源或高風險動作不能由單一人員獨立完成；至少兩名授權者共同存在、確認或執行。**

NIST/CNSSI 的核心概念是：至少兩名 authorized persons，而且彼此能察覺錯誤或未授權程序。

---

## 4.2 題庫最常用的語意

```text
One person cannot do it alone
→ attacker/insider must collude with another authorized person
```

所以 LearnZapp 那句：

> It forces collusion for unauthorized access.

雖然 `forces collusion` 英文讀起來很怪，但它的安全含義是：

> **單一惡意內部人員不夠，至少還要拉另一名授權者一起作弊。**

---

## 4.3 它不需要兩套 IAM

你之前質疑：

> 為什麼不是 two different IAM matrices？一套 IAM 裡面也能建立兩個不同身分／approval matrix。

你的理解是對的。

TPI 是：

> **policy / authorization condition**

不是：

> **必須部署兩套 IAM system**

完全可以：

```text
One IAM platform
Rule:
Action X requires approver A + approver B
```

所以「requires two different IAM matrices」不是 TPI 的定義。

---

## 4.4 TPI vs SoD vs Split Knowledge

| 概念 | 核心問題 | 最短例子 |
|---|---|---|
| **TPI / dual authorization** | 一個敏感動作是否必須兩人共同完成？ | production HSM key ceremony 需兩人 |
| **SoD** | 衝突權限是否拆給不同角色？ | 建立 vendor 與核准付款分開 |
| **Split Knowledge** | 是否沒有人單獨知道完整 secret？ | secret 拆成多份 |

### 口訣

```text
TPI = 兩人一起做
SoD = 工作拆開做
Split Knowledge = 秘密拆開知道
```

### 關係

TPI 可以被視為一種 dynamic separation of duty / dual authorization 實作，但三個詞不要當同義詞。

# 5. 今日錯題：Cloud Security Controls 與 Financial Benefit

題目核心：

> Cloud migration 可能省錢，但什麼會侵蝕實際 financial benefit？

答案：

> Security controls and countermeasures

分類：`[J]`

---

## 5.1 Security controls 只代表 network/software controls 嗎？

**不是。**

Security controls 是上位集合，可包含：

- 技術／邏輯控制：WAF、MFA、KMS、DLP、SIEM
- Network controls：Firewall、segmentation、VPN、ZTNA
- 管理控制：policy、training、audit、change management
- Physical/environmental controls：guard、CCTV、HVAC、generator

但在這題「CSC migration TCO」語境中，題庫主要想的是：

> **customer 額外要付的 technical / operational / compliance security overhead。**

例如：

```text
Cloud base price
+ WAF
+ KMS/HSM
+ SIEM/logging
+ DLP
+ backup/replication
+ private connectivity
+ audit/compliance
= Real TCO
```

### 最短模型

> **Cloud list price ≠ Cloud TCO。**

# 6. 今日錯題：CSA Notorious Nine / Data Loss

分類：`[Q]`

題目引用的 Notorious Nine 是舊版 threat taxonomy；現行 CCSP 重點是 common cloud threats，不值得背 2013 九項名稱。

題目想做：

```text
Lost crypto key       → data inaccessible
Bad backup            → cannot recover
Accidental overwrite  → original data lost
Improper policy       → 題庫認為較「間接」
```

但是：

```text
Improper retention policy
→ delete data too early
→ 也可以直接造成 data loss
```

所以：

> **不要背「improper policy 不會造成 data loss」。**

只保留底層模型：

> **題庫在比較 direct mechanism vs indirect governance cause。**

# 7. 今日總結：最短模型牆

```text
Process isolation
= separate execution domain
≠ no Internet

ISO 27018
= public cloud + PII + CSP acting as processor

Secure KVM

TPI

TPI / SoD / Split Knowledge
= 兩人一起做 / 工作拆開做 / 秘密拆開知道

```
