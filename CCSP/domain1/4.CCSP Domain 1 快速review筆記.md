

## 1. Domain 1 在考什麼

**核心不是技術深度，而是：**

- 雲端概念
    
- 角色責任
    
- 服務模型
    
- 部署模型
    
- shared responsibility
    
- portability / lock-in
    
- governance 與雲端特性影響
    

---

## 2. 角色責任秒殺

### Data Owner

- 定義資料保護需求
    
- 決定：
    
    - classification
        
    - retention
        
    - access requirement
        
    - encryption requirement
        

### Custodian

- 負責實作與維運
    
- 依 owner 要求執行控制
    

### Cloud Service Provider (CSP)

- 提供雲端服務能力
    
- 不等於定義業務安全需求
    

### Cloud Service Partner

- 提供整合、顧問、評估、支援
    

### Cloud Administrator

- 負責日常雲端管理
    
- 在混合/多雲中重點常是 **consistent governance**
    

### 口訣

**Owner 定義，Custodian 執行，Provider 提供，Partner 協助。**

---

## 3. SaaS / PaaS / IaaS 秒殺

### SaaS

- 客戶管理最少
    
- provider 管最多
    
- 優勢：降低維運與更新負擔
    

### PaaS

- 中間型
    
- provider 管 platform
    
- customer 管 app / data / 部分 config
    

### IaaS

- 客戶管理最多
    
- customer 要管 OS、app、data、較多 security config
    

### 題目若問「最重要考量」

先想：

- **security responsibility 怎麼分**
    
- 不是先想價格或彈性
    

### patching 記法

- **SaaS：provider 最多**
    
- **PaaS：共享**
    
- **IaaS：customer 最多**
    

### 口訣

**SaaS 最少自管，IaaS 最多自管。**

---

## 4. 部署模型秒殺

### Public Cloud

適合：

- 快速部署
    
- 高彈性
    
- DevOps / innovation / scale
    

### Private Cloud

適合：

- 高控制
    
- 高客製
    
- 較嚴格治理需求
    

### Hybrid Cloud

適合：

- 同時要控制 + 彈性
    
- 敏感 workload 留內部
    
- 非敏感 workload 上公雲
    

### Community Cloud

適合：

- 有共同需求的特定群體/產業
    
- 不是所有合規題都選它
    

### 口訣

- **要敏捷 → Public**
    
- **要控制 → Private**
    
- **兩種都要 → Hybrid**
    
- **共同需求群體 → Community**

## 5. Shared Responsibility 秒殺

### 大原則

CSP 不會負責一切。  
雲端只是**責任重新分配**。

### 題目判斷方式

先問：

1. 題目在問哪一層？
    
2. 該層是 provider 管，還是 customer 管？
    

### 常見考法

- SaaS：客戶責任最少，但 **data / access / usage** 仍常在客戶側
    
- IaaS：客戶責任顯著增加
    
- PaaS：常考「誰負責 app 與 data」
    

### 口訣

**上層越多自己管，責任越大。**

## 6. Vendor lock-in / Portability 秒殺

### 正確方向

避免 lock-in 最常見答案：

- cloud-agnostic architecture
    
- standard data formats
    
- open standards
    
- decoupling from provider-specific services
    

### 錯誤直覺

不要先選：

- 深度綁定 provider proprietary features
    
- 完全依賴單一廠商原生能力
    

### Containerization

- 增加 portability / consistency
    
- 不是自動安全
    
- 安全仍取決於設定與治理
    

### 口訣

**避免 lock-in 靠標準化，不靠專屬化。**

---

## 7. 雲端特性秒殺

### Broad Network Access

影響：

- 多種 client / endpoint
    
- 複雜度上升
    
- troubleshooting 更難
    

### Rapid Elasticity

代表：

- 自動擴縮
    
- 架構要適合擴縮
    
- 偏好 **stateless / loosely coupled**
    

### Resource Pooling

代表：

- 多租戶共享資源
    
- 隔離與邏輯分割很重要
    

### Measured Service

代表：

- 可量測、可計費、可追蹤使用量
    

### 口訣

- **Broad access → endpoint 複雜**
    
- **Elasticity → 架構要能自動伸縮**
    
- **Pooling → 多租戶隔離**
    
- **Measured service → usage 可度量**

## 8. Governance / Accountability 秒殺

### accountability 最強證據

- **audit trail / log / traceability**
    
- 不是 policy 文件本身
    

### 混合雲 / 邊緣 / 多雲 常見主答案

- consistent governance
    
- policy enforcement
    
- compliance alignment
    
- centralized oversight
    

### SaaS adoption 對 IT 的影響

- IT 不會消失
    
- 角色轉向：
    
    - vendor management
        
    - service integration
        
    - governance
        
    - identity / compliance
        

### 口訣

**Policy 是宣告，audit trail 才是證據。**

## 9. 標準與框架秒殺

### CSA CCM

- Cloud Controls Matrix
    
- control mapping / security assessment
    

### ISO/IEC 27017

- cloud-specific security guidance
    

### FIPS 140-2

- cryptographic module validation
    
- 高 level 代表更強 tamper resistance / protection
    

### 口訣

- **CCM 偏控制矩陣**
    
- **27017 偏雲端安全指引**
    
- **FIPS 140-2 偏加密模組**

## 10. 考場排除法

### 看到角色題

先分：

- 誰定義
    
- 誰執行
    
- 誰提供服務
    
- 誰做支援
    

### 看到 SaaS/PaaS/IaaS

先分：

- 哪層資產在問
    
- 誰負責那一層
    

### 看到 Public/Private/Hybrid/Community

先看：

- 是要敏捷？
    
- 要控制？
    
- 還是混合需求？
    

### 看到治理題

優先選：

- consistent
    
- centralized
    
- auditable
    
- scalable
    

不要先被單一技術控制帶走。

---

## 11. 高頻誤選提醒

### 誤區 1

把 **執行者** 選成 **決策者**

- Custodian ≠ Data Owner
    

### 誤區 2

只看功能，不看責任切線

- 服務模型題最常失分點
    

### 誤區 3

看到合規/敏感就亂選 Community Cloud

- 很多時候其實是 Hybrid
    

### 誤區 4

看到 portability 只想到容器

- 真正更上位的是標準化與去專屬依賴
    

### 誤區 5

看到 accountability 就選 policy

- 真正證據通常是 audit trail
    

---

## 12. 最後口訣總表

- **Owner 定義，Custodian 執行**
    
- **SaaS 最少自管，IaaS 最多自管**
    
- **服務模型先看責任，不先看價格**
    
- **混合需求先想 Hybrid**
    
- **避免 lock-in 靠標準化**
    
- **Rapid elasticity 要靠 stateless**
    
- **Policy 是宣告，audit trail 才是證據**
    
- **多雲/混合雲題，優先想 governance consistency**
